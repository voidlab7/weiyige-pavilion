# 产品知识维护技能

## 概述

产品状态文档是 PM（枢）的持续产出物——不是一次性 PRD，而是随产品演进持续更新的「活文档」。

**核心价值**：
- **省 Token** — 读 200 行文档 ≈ 800 token，扫代码可能 5000-20000 token
- **保意图** — 代码只说「怎么做」，文档说「为什么」和「不做什么」
- **跨角色共享** — 矩/绘/鉴/铸 都能快速对齐产品理解，无需各自考古

---

## 存放位置

产品状态文档是**项目级**文件，放在各项目的 `ai-workspace/` 或 `.weiyige/` 下：

```
项目根目录/
└── ai-workspace/
    └── product-state.md    ← 产品状态文档（PM 维护）
```

**不是**放在角色的 `memory/` 里——因为所有角色都需要读取。

## 更新触发规则

| 触发时机 | PM 做什么 |
|---------|-----------|
| 新需求讨论完成 | 更新功能清单（新增条目，状态=📋规划中）|
| PRD 批准后 | 更新功能状态为 🚧开发中 |
| 功能上线后 | 更新状态为 ✅已上线，记录最终交互说明 |
| 砍需求/改设计 | 更新 NOT in Scope 或修改功能描述 + 写决策日志 |
| 重大架构变更 | 更新「技术约束」（简要描述对产品的影响）|

## 与其他文档的关系

```
产品状态文档（本文件）
├── 是什么 / 为什么 / 不做什么    ← PM 维护，全角色读取
│
PRD（prd-template.md 产出）
├── 单次功能的详细方案              ← 功能开发时使用，完成后精华沉淀到状态文档
│
架构文档（矩产出）
├── 怎么搭 / 技术选型              ← 开发者参考
│
代码
├── 具体实现                        ← 最终真相，但不含意图
```

**原则**：
- 产品状态文档 = 高频读取的「产品记忆」，精简、聚焦、持续更新
- PRD = 单次功能的完整方案，功能上线后不再频繁引用
- 代码 = 只在需要验证细节时才去分析

## 质量标准

- [ ] 任何新角色加入团队，读完此文档 2 分钟内能理解产品全貌
- [ ] 文档与实际代码无重大矛盾（每月自检一次）
- [ ] 功能清单状态与实际一致（功能上线后 24h 内更新）
- [ ] 决策日志记录了所有「为什么选 A 不选 B」的关键拐点
