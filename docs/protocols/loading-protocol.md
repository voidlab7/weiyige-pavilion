# 加载协议解读

> 为什么分三级加载？协议本身在 `.weiyige/LOADER.md`，这里是设计意图。

---

## 解决的问题

角色激活时一次性加载所有文档（IDENTITY + SOUL + PROTOCOL + MEMORY），上下文浪费严重。一个简单问题也要花 5000 token 加载角色——80% 是无用信息。

## 为什么分三级

```
L0（身份卡片）  ← 500 token，"我是谁"
L1（方法论）    ← 1000-5000 token，"我怎么干活"
L2（领域知识）  ← 按需，"我知道什么"
```

**核心洞察**：大部分交互只需要 L0。

- "快速看一下这个方向" → L0 足够（锋的身份卡片就够做判断）
- "全面审查这个架构" → 需要 L1（矩的方法论：审查清单、评分维度）
- "上次那个项目的教训是什么" → 需要 L2（memory 中的历史知识）

## 各级触发条件

| 层级 | 自动加载 | 触发词 |
|------|---------|--------|
| L0 | 角色被路由激活时 | 无需触发 |
| L1 | Deep/Team 模式 | `@soul` `@deep` `深度模式` |
| L1 | 角色需要执行核心职责（非简单问答） | 智能判断 |
| L2 | 任务涉及特定技能/历史知识 | 按需 |

## 与模式的对应

| 模式 | 加载深度 | 场景 |
|------|---------|------|
| Quick | L0 only | "快速看一下""简单问个" |
| Standard | L0，需要时 L1 | 日常任务 |
| Deep | L0 + L1 | 大版本、全面审查 |
| Team | L0 + L1 | 启编排多角色 |

## 效果

| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| Quick 场景 token | ~2000-5000 | ~100-200 |
| token 节省率 | — | 50-90% |

## 设计决策

- **SHARED.md 只加载一次**：多角色串行时不重复加载公共规则
- **SOUL.md 不是必读**：Quick 模式可以不加载——这和早期 CLAUDE.md 的"SOUL.md 必读不可跳过"矛盾，后者已修正
- **判断标准**：如果 IDENTITY.md 中的信息足够完成任务，不加载 SOUL.md
