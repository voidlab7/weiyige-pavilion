# 维弈阁架构分析与改进方向

> 2026-05-12 · 隐·智囊深度分析

## 五大核心能力

1. **单角色独立执行** — 每个角色可以单独作为 Agent 使用（@矩 审查方案、@铸 修 Bug）
2. **多角色串联编排** — team 模式下启·执事串联多个角色完成全链路（砺→锋→枢→矩→铸→鉴→盾）
3. **多项目并发** — 不同项目可同时执行各自的 Agent 任务，互不干扰
4. **多平台兼容** — 支持 CodeBuddy / OpenClaw / Claude Code 等不同 AI 平台
5. **可视化监控** — ops 调度中心 + Electron App + hook 心跳 + CLI 工具链

## 架构分层

```
L4 可视化层  — Electron App（全局看板 + 项目详情 + 动态时间线）
L3 调度层    — weiyige-ops（projects.yaml + 调度得分 + 夜巡 + CLI 工具链）
L2 编排层    — 执事·启（team 模式 / 角色扮演 / task 同步）
L1 角色层    — 13 个角色（.weiyige/ 协议驱动，Markdown 定义）
L0 基础设施  — state.json 状态机 + hook 心跳 + ai-workspace 目录规范
```

## 优点

### 1. 架构分层清晰，渐进式复杂度
每一层解耦，可以单独使用也可以叠加。用 1 个角色的人能用，管 10 个项目的人也能用。

### 2. 协议驱动而非代码驱动
角色定义是 Markdown，不绑定任何 AI 平台。用户改一个 md 就能调角色行为，不需要编程。git diff 就能看到角色变了什么。

### 3. 单人场景真正跑通
不是概念设计，是实际在用——10 个项目、13 个角色、有真实踩坑和修复记录。

### 4. ops 可视化是差异化竞争力
大部分 Agent 框架只管执行不管观测。维弈阁做了从执行到观测的闭环：state.json → health-checker → Electron App → hook 亮灯。

## 缺点与改进方向

### 1. 协议遵从靠自觉，没有强制层 ⭐ 最大风险

**现象**：Agent 写 todos.json 而不是用 CLI、team 模式不调 update-phase、finish 后忘移 queue 到 done。

**根因**：协议写在 md 里，LLM 不一定读、读了不一定遵守。

**改进方向**：把确定性操作从「协议约束」变成「代码强制」。weiyige-cli 已开始做（init-task / update-phase / finish-task / add-queue），继续扩大覆盖面。终极目标：Agent 没有手动写 state.json 的机会，所有状态操作只能通过 CLI。

### 2. 上下文窗口压力

**现象**：13 角色 × (IDENTITY + SOUL + PROTOCOL + memory) = 大量 token 消耗在读协议上。

**改进方向**：角色定义做分级加载——核心指令 < 500 token，详细方法论按需加载。

### 3. 跨项目通信不存在

**现象**：项目 A 和项目 B 的 Agent 完全隔离，无信息交换。

**现状**：当前项目间依赖很弱，暂不紧急。如果将来做 monorepo 产品矩阵，需要跨项目通信机制。

### 4. 没有回滚和审计追踪

**现象**：Agent 改坏文件后无法自动回滚。state.json 记录了「做了什么」，但产物没有版本快照。

**改进方向**：weiyige-cli 在阶段完成时自动 git commit。

### 5. 多平台兼容是理论上的

**现象**：CLI 用 node 绝对路径，换到 OpenClaw 环境需要适配。hook 心跳只支持 CodeBuddy。

**改进方向**：CLI 做环境自适应（检测 $CODEBUDDY_PROJECT_DIR / $CLAUDE_PROJECT_DIR），hook 按平台分支。

## 评分

| 维度 | 评分 | 说明 |
|------|------|------|
| 架构设计 | 9/10 | 分层清晰，渐进复杂度 |
| 实际可用性 | 7/10 | 能用，但协议遵从率不够高 |
| 差异化 | 8/10 | ops 可视化是独有的 |
| 可推广性 | 6/10 | 依赖绝对路径、依赖特定平台特性 |
| 健壮性 | 5/10 | 协议靠自觉、无回滚、状态脏数据频发 |

## 优先改进路线

```
P0（正在做）：CLI 强制化 — 把更多操作变成脚本
P1（短期）  ：角色分级加载 — 减少 token 消耗
P2（中期）  ：自动 git commit — 阶段完成时快照
P3（远期）  ：跨项目通信 + 多平台自适应
```

## 核心判断

> 架构和方向是对的，短板在执行层的纪律性。解决方案不是写更多 md，而是把更多操作变成脚本强制。weiyige-cli 是正确的路，继续走。
